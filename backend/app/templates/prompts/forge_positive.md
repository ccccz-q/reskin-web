
## required —— 用户**明确要求出现**在画面里的东西
只提取有明确「要求出现 / 必须有 / 要有 / 按××游戏（的世界观UI）」语义的条目。
每一项：name 是元素名称，keywords 是 2–5 个**具象名词**关键词
（如「准星符号」→ ["准星", "十字瞄准"]；「复古像素按钮」→ ["按钮", "复古按键"]）。
★ keywords 禁止使用「文字 / 元素 / 内容 / 东西 / 图案 / 样式 / 部分」这类泛词
—— 泛词会误杀应有的通用禁止项。拿不准的不算，宁缺勿滥。

## preserves —— 用户**明确要求按某张图保留某个区域的内容与位置**
如「按照理想图保留顶部的死亡界面布局」「保留参考图左下角文字的位置和内容」。
每一项：name 是区域内容名，region 是**位置描述**（如"画面顶部居中"），
content 是该区域必须严格保留的具体内容与样式，keywords 是 2–4 个具象名词。
★ 这是最高优先级要求：用户指定了「哪里保留什么」，提炼出的提示词必须
让该区域的位置与内容严格复现，不得挪动、缩放或改写。

## removals —— 用户**明确要求去掉 / 忽略**的参考图部分
如「参考图里的树木背景去掉」「不要原图的灰色按钮」。没有就空数组。
只记录用户**明确**提出的去除要求，不许自行推断。

用户没有任何明确要求时，三类都是空数组 —— 绝不许替用户发明要求。

只返回 JSON：
{
  "required": [{"name": "...", "keywords": ["..."]}],
  "preserves": [{"name": "...", "region": "...", "content": "...", "keywords": ["..."]}],
  "removals": ["..."]
}
